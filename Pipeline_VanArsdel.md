# 🏗️ Архитектурный пайплайн: Диагностика причин потери рыночных позиций VanArsdel

## 1. Контракт данных (Data Contract)
- **Бизнес-цель**: Перераспределить ресурсы с неэффективного "динамического ценообразования" на исправление базовых цен, очистку MDM и аудит региональной дистрибуции.
- **Источник**: `VanArsdel_Cleaned.csv` (результат прохождения QA Gate 1).
- **Гранулярность (Grain)**: Уникальная транзакция (`product_id`, `date`, `zip`).
- **Ожидаемые артефакты**: 4 структурированных CSV-файла + аналитическая записка.

## 2. Этап 1: Ingestion & QA Gate 1 (Загрузка и контроль качества)
*Выполняется скриптом предобработки.*
- **Нормализация**: Приведение колонок к `snake_case`.
- **Типизация**: `date` → `datetime64`, `zip` → `str` (с `zfill(5)`), категориальные признаки → `category`.
- **Булева логика**: Унификация `is_van_arsdel`, `is_compete`, `mfg_is_van_arsdel`, `is_compete_hide` в тип `boolean`.
- **QA Gate 1 (Блокирующий)**: Пайплайн останавливается, если обнаружены: `NaT` в дате, `units <= 0`, `revenue < 0` или полные дубликаты строк.

## 3. Этап 2: Feature Engineering & QA Gate 2
*Создание признаков строго из существующих данных (без внешних гипотез).*
- `transaction_price` = `revenue` / `units` (float64)
- `year` = `date.dt.year` (int32)
- `month` = `date.dt.month` (int32)
- `is_va` = `is_van_arsdel` (boolean, алиас для удобства)
- `is_hidden` = `is_compete_hide` (boolean, алиас для удобства)
- **QA Gate 2**: Проверка отсутствия деления на ноль (`units == 0` уже отфильтровано на Этапе 1) и логической непротиворечивости (`is_va` и `mfg_is_van_arsdel` должны быть коррелированы).

## 4. Этап 3: Аналитические потоки (4 независимых модуля)

### 4.1. Поток А: Ценовая эластичность (Price Elasticity)
- **Grain**: `product_id`, `year`
- **Фильтр**: `is_va == True`
- **Агрегация**: `avg_price` (mean), `total_units` (sum), `transactions` (count).
- **Расчёт**: Сортировка по `product_id`, `year`. Вычисление YoY `%Δ_price` и `%Δ_units`.
- **Метрика**: `elasticity_coeff` = `%Δ_units` / `%Δ_price`.
- **Выходной артефакт**: `elasticity_yoy_2011.csv`

### 4.2. Поток Б: Аудит MDM ("Мёртвый" ассортимент)
- **Grain**: `product_id`
- **Фильтр**: `is_va == True`
- **Агрегация**: `last_sale_date` (max), `category` (first), `is_hidden` (max).
- **Расчёт**: `max_dataset_date` = `df['date'].max()`. Флаг `is_dead` = `last_sale_date` < (`max_dataset_date` - 2 года).
- **Итог**: Фильтрация `is_dead == True` & `is_hidden == True`.
- **Выходной артефакт**: `dead_sku_audit_list.csv`

### 4.3. Поток В: Волатильность цен (Dynamic Pricing Myth)
- **Grain**: `product_id`, `year`
- **Фильтр**: `is_va == True`, `transactions` > 1 (исключение шума единичных продаж).
- **Агрегация**: `mean_price`, `stddev_price`, `max_price`, `min_price`.
- **Расчёт**: `price_volatility_pct` = (`stddev_price` / `mean_price`) * 100. `max_deviation_pct` = (`max_price` - `min_price`) / `mean_price` * 100.
- **Выходной артефакт**: `price_volatility_by_sku.csv`

### 4.4. Поток Г: Географические пробелы (Geographic Gaps)
- **Grain**: `zip`, `region`
- **Логика**: 
  1. `zips_va` = set уникальных `zip` где `is_va == True`.
  2. `zips_comp` = set уникальных `zip` где `is_va == False`.
  3. `gap_zips` = `zips_comp` - `zips_va`.
- **Обогащение**: Маппинг `gap_zips` к `region` через исходный датафрейм.
- **Выходной артефакт**: `regional_zip_gaps.csv`

## 5. Этап 4: Визуализация и Интерпретация
- **График 1 (Line/Bar Combo)**: Динамика `avg_price` и `total_units` по годам (Топ-20 SKU). *Цель: Визуализация отрицательной эластичности.*
- **График 2 (Stacked Bar)**: Кол-во "мёртвых" SKU (`is_dead == True`) по `category`. *Цель: Подтверждение концентрации в Urban.*
- **График 3 (Boxplot)**: Распределение `price_volatility_pct`. *Цель: Демонстрация низкой базовой волатильности (~1.8%) с редкими выбросами.*
- **График 4 (Stacked Bar/Map)**: Покрытие ZIP-кодов по регионам (VanArsdel vs Competitor_Only). *Цель: Визуализация пробела в West и East.*

## 6. Этап 5: Архитектурные ограничения и QA Sign-off
- [x] **Grain**: Соблюден на каждом этапе агрегации (Транзакция → SKU/Год → Регион).
- [x] **Leakage**: Отсутствует. Расчёты YoY и волатильности используют только исторические данные в рамках заданного окна. Временное разбиение строго соблюдается.
- [x] **Галлюцинации**: Все поля являются строгими производными от исходных 18 колонок. Новые сущности не выдуманы.
- [x] **Трассируемость**: Каждый из 4-х диагностических выводов напрямую связан с конкретным блоком кода в Этапе 3.
- [x] **Безопасность**: Используются относительные пути. Код модульный и воспроизводимый.

## 7. Рекомендации (Actionable Insights)
1. **Ценообразование**: Внедрить guardrails: блокировка повышения базовой цены >5% для товаров с эластичностью < -1.0 без многоуровневого согласования.
2. **MDM**: Перевести все SKU с `is_hidden == True` и `days_since_last_sale` > 730 в архивный справочник. Исключить из KPI "широта ассортимента".
3. **Контроль скидок**: Автоматическое создание тикета на аудит при `price_volatility_pct` > 5% для конкретного SKU.
4. **Дистрибуция**: Перенаправить маркетинговый бюджет на аудит логистических издержек и renegotiation контрактов в регионах West и East.
