# 📄 Метадата и Контракт данных: VanArsdel Sales Transactions
## 1. Контракт данных (Data Contract)
* **Бизнес-цель**: Перераспределить ресурсы с неэффективного "динамического ценообразования" на исправление базовых цен, очистку MDM (Master Data Management) и аудит региональной дистрибуции.
* **Источник**: `VanArsdel.csv` (сырой входной файл).
* **Гранулярность (Grain)**: Уникальная транзакция на уровне комбинации `(product_id, date, zip)`.
* **Объём данных**: 158 177 строк, 18 исходных колонок (после удаления 1 полного дубликата: 158 176 строк).
* **Ожидаемые артефакты пайплайна**: 4 структурированных CSV-файла (`dead_sku_audit_list.csv`, `price_volatility_by_sku.csv`, `regional_zip_gaps.csv`, +1 итоговый) + аналитическая записка.

## 4. Контроль качества (QA Gates)

### 🛑 QA Gate 1 (Блокирующий, на входе)
Пайплайн **немедленно останавливается**, если обнаружено любое из следующих условий. *По результатам аудита исходного файла:*
1. Наличие `NaT` (Not a Time) в колонке `date` → **Факт: 0 записей (PASS)**.
2. Наличие значений `units <= 0` → **Факт: 0 записей (PASS)**.
3. Наличие значений `revenue < 0` → **Факт: 0 записей (PASS)**.
4. Наличие полных дубликатов строк → **Факт: 1 запись (индексы 26879, 26880)**. *Решение: Автоматическое применение `df.drop_duplicates()` перед дальнейшей обработкой.*

### ⚠️ QA Gate 2 (Логический, после нормализации и Feature Engineering)
1. **Деление на ноль**: Исключено, так как `units == 0` строго отфильтровано на Этапе 1.
2. **Логическая непротиворечивость MDM**: Проверка корреляции между `is_van_arsdel` и `mfg_is_van_arsdel`. 
   * *Факт аудита*: Конфликтов (`is_van_arsdel == True` при `mfg_is_van_arsdel == False` или наоборот) не обнаружено (0 записей). **PASS**.
3. **Уникальность по Grain**: После применения `drop_duplicates()` комбинация `(product_id, date, zip)` гарантированно уникальна для каждой строки.

## 5. Архитектурные гарантии (согласно preprompt)
* **Leakage (Утечка данных)**: Отсутствует. Все производные признаки (`year`, `month`, `transaction_price`) вычисляются строго из атомарных данных текущей строки. Будущие агрегации (YoY, волатильность) будут использовать только исторические данные в рамках заданного окна.
* **Галлюцинации**: Все 23 поля (18 исходных + 5 производных) являются строгими производными от исходного набора. Новые сущности, справочники или внешние гео-данные не выдумываются.
* **Трассируемость**: Каждое бизнес-требование из Контракта данных трассируется до конкретного правила валидации или формулы в этом словаре.
* **Оптимизация ресурсов**: Использование типа `category` для строковых колонок с низкой кардинальностью (Region, State, Segment, City) и `boolean` вместо `str` для флагов снижает потребление памяти с исходных 34.1 MB до ~15-18 MB и ускоряет операции группировки (groupby) на Этапе 3 пайплайна.
